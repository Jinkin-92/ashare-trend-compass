# A 股趋势罗盘 — 使用说明书

> 适用版本：V0.6 列表页 + V0.7 详情页
> 最后更新：2026-07-09

---

## 1. 这是什么

**A 股趋势罗盘**是一个本地部署的辅助工具，帮助"顺势交易者"在两个层面做决策：

- **什么时候动手（择时）** → 看**趋势温度**（七档）+ **右侧状态**
- **动哪个品种（选筹）** → 看**趋势相对强度**（1-99 分位）

数据每日盘后更新一次（最新一日 = `2026-07-08` 截面）。**不构成投资建议**，仅作为研究工具。

## 2. 快速开始

```bash
# 1. 进入项目目录
cd "stock analysis/ashare-trend-compass"

# 2. 启动本地静态服务器
python scripts/serve_web.py
# 服务地址：http://127.0.0.1:8080

# 3. 浏览器打开
# 列表页： http://127.0.0.1:8080/
# 详情页： http://127.0.0.1:8080/detail.html?symbol=IDX_000001
```

如果当日数据未更新，先跑一次管道：
```bash
python scripts/run_pipeline.py            # 完整跑
python scripts/run_pipeline.py --calc-only  # 只重算指标
python scripts/export_static.py          # 重导出 JSON
```

## 3. 列表页（`index.html`）

### 3.1 整体布局（自上而下）

```
┌────────────────────────────────────────────────┐
│ ① 顶部详情卡 (A 股整体)                          │
├────────────────────────────────────────────────┤
│ ② 品种列表 (按一级行业分组)                       │
│    工具栏: [分组] [温度] [仅右侧] [搜索]            │
│    每个分组下是一张表:                            │
│    品种 | 最新价 | 日涨幅 | 温度 | 右侧天数 | RS | 成交额 │
└────────────────────────────────────────────────┘
```

### 3.2 ① 顶部详情卡

显示 **A 股整体**（用上证指数 `IDX_000001` 作为代理，因没有自建 A 股根节点指数）的核心指标：

| 字段 | 含义 | 单位 / 取值 |
|---|---|---|
| **最新价** | 上证指数 2026-07-08 收盘价 | CNY，保留 2 位小数 |
| **日涨幅** | 当日 close vs 昨日 close | %，涨红跌绿 |
| **趋势温度** | 七档分类 | 沸 / 热 / 温 / 平 / 凉 / 寒 / 冻 |
| **趋势相对强度（RS）** | 在 7 个指数内排名的百分位 | 1-99 分位 + 箭头 |
| **区间累计** | 当前选中窗口的累计涨幅 | % |
| **趋势图** | 累计涨幅曲线 | 见 §3.3 |

**窗口按钮**：`近 3 月` / `近 1 年`（默认 1 年）
**坐标按钮**：`线性坐标`（默认）/ `对数坐标`

#### 怎么看趋势图
- **横轴**：日期
- **纵轴**：累计涨幅 %
- **黄色线 + 浅黄填充**：A 股整体
- **横虚线**：每 20% 一格的辅助线（方便"数格子"估算）
- **黄底纹**：A 股整体处于右侧的天数区间

**线性 vs 对数 怎么选？**
- **线性**：直观看出"涨多少 / 跌多少"，适合看短期波动
- **对数**：y 轴为 `log10(1 + 累计涨幅/100)`，把 1% 和 100% 同样显示出来，**适合看长期复利**——能识别出"指数级上涨"和"线性上涨"的区别

### 3.3 ② 品种列表

#### 分组方式
- **按一级行业**（默认）：每个一级行业是表头，下面是它的二级行业 + 包含的指数
- **按二级行业**：直接列所有 131 个二级行业
- **指数**：只看 7 个宽基指数

#### 工具栏筛选
- **温度**：选 7 档中的 1 档，仅显示该温度的品种
- **仅右侧**：勾选后只保留 `is_right_side=true` 的品种
- **搜索**：按名称/代码模糊搜索

#### 表头点击排序
所有表头可点击切换升降序。点击 **温度** 按档位排序（沸>热>温>平>凉>寒>冻），点击 **右侧天数** 默认倒序（有数据的先看）。

#### 行内字段含义

| 字段 | 含义 | 颜色 / 单位 |
|---|---|---|
| **品种（链接）** | 名称 + 代码 | 名称是 SW 申万行业的官方中文名，代码如 `SW_801010` |
| **最新价** | 收盘点位 | 指数 4 位小数，行业 2 位 |
| **日涨幅** | 当日 vs 昨日 | %，涨红跌绿（A 股惯例） |
| **温度** | 七档色块 + 文字 | 见 §6 |
| **温度副标** | 名称下方的 `温→平` 之类小标签 | **仅当今日温度与昨日不同时显示**；如"平→沸"表示昨日平、今日沸 |
| **右侧天数** | 进入右侧的自然日数 | 仅 `is_right_side=true` 时显示 `+N` |
| **RS** | 在同 `node_type` 全局百分位 | 1-99 + 趋势箭头 ↑/↓/↓↓ |
| **成交额** | 当日累计成交额 | 元（自动转为万/亿/万亿） |

#### 整行高亮
**橄榄黄底色** = `is_right_side=true` 的品种，表示它处于右侧状态机内。

- 一级行业：`SW_801010` / `SW_801030` / ...

```

主图: 黄色实线 = 当前品种
基准: 灰色虚线 = 沪深300 (benchmark)
黄底纹: 该品种处于右侧的时间段

#### 图 2: 温度历史时间轴

```
y 轴: 7 档温度（沸/热/温/平/凉/寒/冻，y=7 是沸）
x 轴: 日期
背景色块: 每个时间段是哪种温度
黑线: 折线图看温度变化
```

横线 = 温度档位的位置，**背景色块直接告诉你"那段时间市场对这品种怎么看"**。鼠标 hover 可看当日温度、右侧天数、RS。

#### 图 3: 相对强度走势

```
y 轴: 1-99 分位
x 轴: 日期
蓝线: RS 折线
绿色 ▲: 5 日内 RS 上升 > 5 分
橙色 ▼: 5 日内 RS 下降 5-15 分
红色 ▼: 5 日内 RS 下降 > 15 分
```

**怎么读**：RS 高 = 在同类（个股之间 / 二级行业之间）跑赢多数；箭头变化快 = 排名洗牌快。

### 4.2 怎么"看趋势"

1. **先看温度历史时间轴**（图 2）—— 找出该品种"在沸/热区间待了多久"，长期在热档的品种才是真强势
2. **再看累计收益图**（图 1）—— 验证视觉效果，**黄底纹（右侧区间）正好对应图 2 的热/温时间段**
3. **最后看 RS 走势**（图 3）—— 确认它在同类中是否真跑赢

## 5. 指标含义详解

### 5.1 趋势温度（七档）

| 档位 | 含义 | 多头交易含义 | 空头交易含义 |
|---|---|---|---|
| **沸** | 快速拉升，波动放大 | 泡沫区，避免追高 | — |
| **热** | 上涨行情确认 | 右侧确认，尽快建仓 | — |
| **温** | 盘整有启动迹象 | 预警区，监测买点 | 预警区，监测卖点 |
| **平** | 横盘 | 观望 | 观望 |
| **凉** | 盘整有下跌迹象 | （对称）| 预警区，监测卖点 |
| **寒** | 下跌行情确认 | — | 右侧确认，尽快离场 |
| **冻** | 快速下跌，波动放大 | — | 超跌区，避免抄底杀跌 |

**算法**：七档由三维度分数合成：
1. **趋势方向分**（±30）：价格 vs MA60 + MA20 vs MA60 的排列
2. **动量分**（-30 ~ +30）：20/60/120 日 ROC 加权，近期权重高
3. **波动扩张分**（±10）：短期 ATR / 中期 ATR > 1.5 时加 +10

分数分档：≥50 沸 / ≥25 热 / ≥5 温 / -5~5 平 / -25~-5 凉 / -50~-25 寒 / ≤-50 冻
（**注：当前算法在某些区间存在跳档情况，V0.9 算法校准阶段会做精细化调整**）

### 5.2 趋势相对强度（RS, 1-99 分位）

类似 IBD 的 RS Rating，**按 `node_type` 在同类型品种内做百分位排名**：

- 7 个指数互比 → RS=66 表示跑赢 66% 的指数
- 131 个二级行业互比 → RS=90 表示跑赢 90% 的二级行业
- 5529 个个股互比 → RS=50 表示中位数

**算法**：用 63/126/189/252 日 ROC 加权（近期权重 0.4），按 trade_date + node_type 排名

**趋势箭头**（基于 5 日前 RS 对比）：
- `↑`：5 日上升 > 5 分
- `↓`：5 日下降 5-15 分
- `↓↓`：5 日下降 > 15 分
- （无箭头）= 横盘或 5 日内无足够历史

### 5.3 右侧状态机（滞后带 / Hysteresis）

**进入右侧**：温度首次达到"热"（含沸），右侧天数 = 1
**维持右侧**：只要温度 ≥ "温"，右侧天数 +1
**退出右侧**：温度跌破"温"（降至平/凉/寒/冻任一档），右侧天数清零

**空头对称**：首次到达"寒"（含冻）进入空头右侧，维持"凉"，升破"凉"退出

**为什么要滞后带**？防止品种在"温/热"分界线附近反复触发导致状态闪烁。

**行内含义**：
- 行末出现 `+18` 表示该品种已连续 18 个自然日处于右侧
- 行底色橄榄黄 = 处于右侧
- 详情页的"右侧区间"黄底纹 = 历史上所有进入并维持右侧的时间段

## 7. 算法参数与校准

### 7.1 当前算法的"已知偏差"

实测发现 7-08 截面 **126/161 = 78% 品种落在"寒"档**——分布严重偏寒。原因可能是：
- 方向分权重过大（±30 在总分里占比太高）
- 波动扩张条件（ATR5/ATR60 > 1.5）容易误触发
- 个股 vs 指数 vs 行业 用同一套分数标准，未按品种特征分档

**这些问题属于 V0.9 算法校准阶段的范畴**，需要你提供连续 5 日的参考数据（PRD 7.1 节模板）才能精确调参。

### 7.2 算法校准流程（V0.9）

如果你有现成的小程序截图或导出的 5 日数据：
1. 选一个二级行业分组（比如"工业配套"7 个品种）
2. 按下表整理 5 个交易日 × 7 个品种的 (温度, RS, 右侧天数)
3. 把表发给我
4. 我跑 `scripts/calibrate.py`（待写）输出"参考值 vs 计算值"对照表
5. 逐个调参到 85%+ 档位一致 / RS 误差 ±5

```

|---|---|---|---|---|---|---|
| 2026-06-29 | 基础耗材 | | | | | |

## 8. 常见问题

### Q1: 为何我的指数显示"寒"但市场感觉不冷？
**A**：温度分数 = 方向分（±30）+ 动量分（±30）+ 波动扩张分（±10）。**单一维度看涨不够**——必须三个维度同时正面才会到"热"。这与"看着涨了"的主观判断可能有差距，是 V0.9 校准的对象。

### Q2: 为何同一品种 7-08 是"寒"但 7-03 是"温"？
**A**：可能 7-04 / 7-07 出现"破位"（跌破 MA60 或短期均线死叉），导致方向分从 +30 跌到 -30。**符合滞后带设计**——温度是按收盘日计算的状态，不带平滑。

### Q3: 为什么没有我的股票？
**A**：当前 MVP 只覆盖指数 + 申万行业 161 个品种。**全市场 5529 只个股**未拉取——需要等数据管道扩展到全 A 股。V1.0 之后。

### Q4: 右侧天数为 0 但行底色不是黄？
**A**：右侧天数 = 0 时**不在右侧**，行底色应是白色。如果行底色是橄榄黄而右侧天数为空，说明渲染逻辑 bug——请截图发我。

### Q5: 对数坐标下，负数怎么处理？
**A**：对数坐标无法表示负数，y 轴只显示 0% 到 +200% 区间。**跌的区间在线性坐标下看更清楚**。

### Q6: 概念板块（半导体/创新药/AI）怎么看？
**A**：**当前不可用**——东财概念日线接口被当前网络代理挡。需要等数据源扩展。

### Q7: 数据多久更新一次？
**A**：每日盘后跑一次 `run_pipeline.py`。**不实时**——日线级别。

### Q8: 为什么温度一天能跳 2-3 档（如寒→沸）？
**A**：当前算法允许"任意跨度"跳档——因为温度 = 方向分 + 动量分 + 波动扩张分 直接合成，不约束连续性。**这不符合直觉**（市场情绪不会一天内瞬间反转），属于已知偏差。
**已决定**：暂不改主公式，**留到 V0.9 算法校准阶段连同其他偏差一起调**。等 Jinkin 提供 5 日参考数据后重写温度计分逻辑（加 1 档/次限制 + 状态机耦合）。

## 11. 反馈渠道

- **bug 报告**：在 `data/logs/pipeline.log` 找错误栈
- **算法偏差**：在 `tests/` 加反例，跑 `pytest tests/`
- **UI 调整**：直接改 `web/css/style.css` + `web/js/`，无需重启服务（Ctrl+F5 硬刷）

**任何想改的细节都可以在 USER_GUIDE.md 后面追加 FAQ 节**。
